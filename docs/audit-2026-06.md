# LG Remote — M3 / Design-System Audit & Design-Iteration Plan

_June 2026. Method: parallel audit of the theme layer, components/screens, and structure, judging the
code **as if the project design system (`docs/design-system.md`) and the `material-3` skill had governed
it from day one** — applying the skill's reference standards (`~/.claude/skills/material-3/references/`).
Plus a researched recommendation for a token-efficient, accurate design-iteration loop._

## Verdict

The foundation is genuinely good: correct Material You dynamic-color + Ultraviolet-fallback wiring, real
token objects (`Space` / `AppShapes` / `MotionSpecs`), honest stock-M3 reuse, and the custom pieces
(gesture pad, `ControlKey`, filled-pill segments) are **justified by the design, not reinvention**. It
reads ~80% "M3-from-the-start". **No correctness bugs.** The 20% gap is concentrated in four areas below.
Intentional divergences (filled-pill segments, recessed pad) are correct per the "native-finish, not
pixel-truth" stance and are **not** defects.

## Design-iteration loop (recommended)

Standout: **Roborazzi (already used) supports a custom `imageComparator` + AI image assertion**, so the
HTML→headless-Chrome→RMSE harness can **fold into Roborazzi** — one render path, one golden store, one CI
step, same fidelity semantics.

**Define → Generate → Verify:**
1. **Define** — design-system.md stays the prose spec; **Material Theme Builder becomes the machine SSOT**
   for colour/type (exports Compose theme + DTCG token JSON the HTML studies can share). Gate with
   `/material-3 audit`. _~0 tokens._
2. **Generate** — author surfaces with **multipreview** (`@PreviewLightDark`, `@PreviewDynamicColors`,
   `@PreviewScreenSizes`) + **Live Edit** for sub-second visual iteration; browse with **Showkase**. The
   zero-token inner loop — do the bulk of styling here before any AI/test runs.
3. **Verify** — keep **Roborazzi**; auto-generate its tests from previews via **ComposablePreviewScanner**
   (no hand-written test per surface); port the RMSE-vs-HTML-reference logic into a **custom
   `imageComparator`**. Reserve **AI visual assertion for a few hero surfaces only** — the one place to
   deliberately spend tokens.

| Option | Trade-off |
|---|---|
| **Recommended** (above) | Cheapest inner loop, deterministic verify, one engine. |
| Official-only (Compose Preview Screenshot Testing, drop Roborazzi) | Google-blessed but **alpha in 2026**, no custom comparator → loses reference-diff. Not yet. |
| AI-screenshot-in-the-loop (render → vision model → edit) | Great for last-5% polish; token-hungry + non-deterministic. Gated critic, not the backbone. |
| Figma-centric | Only if Figma-first (project is HTML-artifact-first); Dev Mode Compose codegen currently buggy. Skip. |

**Drop:** Figma Relay (sunset Apr 2025), Figma Dev Mode MCP for Compose (returns JSX), running two
screenshot engines, AI-vision on every run.
